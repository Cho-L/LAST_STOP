### 1.1 설계 외 코드 동작 (감독 인지 필요)

설계 문서에 없지만 코드에 있는 동작입니다. 승인 여부를 결정해야 합니다.

1. **레벨업 중 전체 정지**: `Time.timeScale = 0`(`P:1354`). 외부·내부 시뮬레이션과 생존 시계가 모두 멈춥니다.
2. **문간 반격(doorway counter)**: 진입 후 0.6초 경직 중 맞은 적은 1.15 넉백되고 경직이 해제됩니다(`P:1145-1153`, `P:1168-1173`).
3. **3타 콤보**: 0.18초 간격, 0.55초 콤보 창. 3타는 최대 3마리 광역 공격입니다(`P:46-47`, `P:921-932`, `P:1159-1183`).
4. **중간 웨이브**: 195초부터 45초마다 2마리를 추가 소환합니다(150~330초 구간, 실제 195/240/285초 3회, `P:724-731`).
5. **차체 보강의 즉시 회복**: 최대치와 현재 HP를 함께 +25(`P:1429-1430`). 설계상 HP 회복 수단은 정의되어 있지 않습니다.
6. **미사용 코드**: `SpawnInteriorEnemy`(`P:1125-1129`, 내부 적에 외부 스프라이트 사용), `DamageNearest`(`P:1199-1213`)는 호출되지 않습니다. 예약 ID(`C:17-21`)와 `EnemyKind.Special/Boss`(`C:27-28`)도 구현이 없습니다.

   - A. 이름을 "콩알포 강화"로 바꾸고 효과(공격력 +1) 유지
   - B. 이름에 맞춰 효과를 공격 속도 증가로 변경 (미사용 `exteriorAttackSpeedMultiplier` 활용)
   - C. 공격력과 속도 카드를 둘 다 둠
   - 추천: **A.** 데모 밸런스를 흔들지 않는 가장 작은 변경입니다. UI 문구라 UI 팀 협의가 필요합니다.

5. **"무기 3 + 지원 2" 분류 확정**
   - A. 무기 = 콩알포·비눗방울·화염기, 지원 = 관통(분열)·차체 보강 (현행 README와 같음)
   - B. 콩알포를 기본 장비로 따로 두고 무기 3종을 별도 정의
   - 추천: **A.** 그대로 승인하고, 데이터 구조(`WeaponSlots 5 / SupportSlots 3`)는 정식판 목표치로 의미를 명시해 주세요.

6. **50마리 경고 이후의 결과**
   - A. 표시·경고음만 (현행)
   - B. 경고 상태에서 외부 화면 테두리 등 추가 시각 경보만 강화
   - C. 경고 상태에서 게임 규칙 변화 (예: 적 공격 속도 상승)
   - 추천: **A 또는 B.** C는 새 메커니즘이므로 별도 설계 승인이 필요합니다. 현재 패배 조건은 HP 0 하나로 유지합니다.

7. **내부 적끼리 겹침 허용 여부**
   - A. 현행 (겹침 허용, 시각적 오프셋만)
   - B. 줄 세우기 (앞 적이 막히면 대기)
   - C. 다수 적이 플레이어를 동시에 공격할 수 있는 수 제한
   - 추천: **A 유지, 플레이테스트 관찰 항목으로 등록.** B·C는 3타 광역과 경고 50 밸런스에 영향이 큽니다.

8. **HUD 중간 경고 단계 16 / 40**
   - A. 현행 승인
   - B. 50 하나로 단순화
   - C. 비율 기반 (예: 50의 30% / 80%)
   - 추천: **A 승인.** 50 규칙을 해치지 않는 표시 보조입니다. 문서화만 필요합니다.

9. **차체 보강의 회복 효과**
   - A. 현행 (최대·현재 +25, 사실상 회복 수단)
   - B. 최대치만 증가
   - C. 데모 회복 수단으로 공식화하고 중복 횟수 제한
   - 추천: **A 유지.** 데모에서 유일한 회복 수단이라 제거하면 난이도가 크게 오릅니다. 설계 문서에 "회복 가능"을 명시해 주세요.

10. **다음 작업의 우선순위**
    - A. 데모 품질 (테스트·사람 플레이·오디오·아트)부터

## 4. 정식판까지 다음 3개 마일스톤 (제안)

> 아래는 모두 **제안**입니다. 엔드리스 주행, 중간 정류장, 자원, 시설, 노선 선택, 수동 조향, 영구 해금은 `GameDesign.md`에 "계획된 후속 시스템"으로만 적혀 있으며 시기와 효과는 감독 승인이 필요합니다. 승인 전에는 어떤 마일스톤도 구현을 시작하지 않습니다.

### M2 (제안) — 데모 확정: 검증 가능한 8분 런

- 목표: 현재 승인 범위(8분, 무기 3 + 지원 2, 적 1종)를 증거와 함께 DONE으로 만듭니다. 새 메커니즘은 추가하지 않습니다.
- 작업 후보:
  - 질문 1~9 결정 반영 (문구·수치만)
  - NUnit EditMode/PlayMode 테스트: 1:1 진입, 실제 명중으로만 HP 감소, 50마리 경고 시 비패배, 480초 도착, R 재시작, 투사체 추적 중단
  - 정상 속도 사람 완주 3회 이상, 패배·도착 기록
  - 오디오 단독 청취, 지붕 무기 아트 재검토 (Art/Sound 팀)
  - 미사용 코드 정리 (`exteriorPlayer`, `SpawnInteriorEnemy`, `DamageNearest`) (개발 팀)
- 의존: 개발 팀(씬 소유), UI 팀(카드 문구), Art/Sound 팀
- 완료 기준: 위 테스트 통과 기록, 사람 플레이 기록, `Tasks.md`의 해당 항목 DONE 전환

### M3 (제안) — 콘텐츠 확장 실험: 적 다양성과 업그레이드 풀

- 목표: 정식판 목표인 "무기 테크 7종 이상, 최대 5부품 조합"에 앞서 데이터 구조와 다양성을 검증합니다.
- 작업 후보 (각각 감독 승인 필요):
  - 콘텐츠 정의를 ScriptableObject로 이전 (`C:62-65` 주석의 계획과 일치, ID 유지)
  - 적 2종 추가 제안서 (`EnemyKind.Special`, `Boss` 활용 여부 결정)
  - 업그레이드 무작위 풀 (질문 3의 C안 승인 시)
  - 무기 4~7번째 후보 기획서 (텍스트 사양만, 에셋 생성 아님)
- 의존: M2 테스트 기반, Art 팀 사양서
- 완료 기준: 기존 8분 데모 회귀 테스트 통과, 새 콘텐츠는 데이터로만 추가 가능

### M4 (제안) — 정식판 루프 프로토타입: 정류장과 지속 주행

- 목표: 계획된 후속 시스템 중 감독이 고른 최소 조합을 회색 박스로 검증합니다.
- 후보 (모두 미승인, 감독 선택 필요):
  - 8분 도착 이후 계속 달리는 엔드리스 모드
  - 중간 정류장에서 정비 (자원 소비, 시설)
  - 정류장 사이 노선 선택
  - 버스 수동 조향
  - 영구 해금 (`C:17-21` 예약 ID: 강아지 라이더, 오토바이, 군인, 장갑차)
- 기획 팀 권장 순서: **엔드리스 주행 → 중간 정류장 + 자원 1종 → 노선 선택**. 수동 조향은 "외부 자동 전투 + 내부 수동 전투"라는 현재 조작 부담 구조를 바꾸므로 가장 마지막에 별도 검토할 것을 권합니다.
- 의존: M3의 데이터 구조, 감독의 시스템별 승인
- 완료 기준: 감독이 승인한 시스템에 대한 수용 기준 문서 선작성 후 구현
