## 2. 960x540 가독성 위험

판정 기준: 960x540에서 본문 최소 16px, 보조 텍스트 최소 14px, 텍스트 박스 세로 높이 ≥ 폰트 × 1.45(Noto Sans CJK 줄 높이 근사). 수치는 추정이며 **실제 측정 필요**.

| # | 위험 | 근거 | 심각도 |
| --- | --- | --- | --- |
| R1 | **작은 글씨**: Hit Source(13.5px), 레벨업 입력 힌트(13.5px), Mode/Experience(15px). Regular 굵기 한글 + 외곽선 없음이라 배경 위에서 획이 뭉개질 가능성 | 480-482, 533 | 높음 (Hit Source는 생존 정보) |

## 3. 디자인 대비 누락된 UI

GameDesign.md의 핵심 루프(1:1 침입, 시점 전환, 공용 HP, 50 경고) 기준.

| # | 누락 | 설명 | 설계 근거 |
| --- | --- | --- | --- |
| M1 | **50 경고 전용 표시** | 50 도달/해제가 화면 전체에서 즉시 읽히지 않음(R7). "즉시 패배가 아님"을 명확히 전달하는 문구도 없음 | "50 is a warning threshold, not an instant defeat" |
| M2 | **시점 전환 인디케이터** | 카메라가 즉시 컷(677-678). 전환 순간 화면 변화 외에 "지금 어느 시점인지"는 중앙 15px Mode 텍스트뿐. 전환 연출(와이프/플래시)과 큰 시점 배지가 없음 | "Switch views and repeat" |
| M3 | **반대 시점 상황 요약** | 내부를 보는 동안 외부 적 수/버스 접근 임박 정보가 없음. 외부를 보는 동안 내부 상황은 숫자(차내 적)와 피격 시 문구만 있음 | "both simulations continue" |
| M4 | **침입 카운트 이벤트 표시** | 침입은 `breaches` 숫자 증가 + 0.65초 색 펄스뿐. "+1 침입" 같은 증분 표시가 없어 1:1 침입이 체감되지 않음 | "one-for-one intrusion" |
| M5 | **피격 대상 위치 표시** | 플레이어 vs 코어 중 무엇이 맞았는지 텍스트로만 표시. 내부 시점에서 화면 가장자리 방향 표시나 코어 위 HP 링이 없음 | 공용 HP, 실제 피격만 데미지 |
| M6 | **저체력 경고** | 30% 이하에서 텍스트·바·코어 색만 바뀜. 화면 가장자리 비네트 등 주변시 경고 없음 | HP 0 = 런 종료 |
| M7 | **조작 안내 상시 표시** | Tab/Space/1·2·3/R 안내가 토스트·액션바에 흩어져 있음. A/D 이동 안내는 HUD 어디에도 없음(README에만 있음) | — |
| M8 | **패배 결과 통계** | 패배 화면에 생존 시간·처치·최고 차내·레벨이 없음(R11) | — |
| M9 | **일시정지 상태 표시** | 레벨업 중 `timeScale = 0`이지만 "일시정지" 표시가 없음. 일반 일시정지 메뉴도 없음(디자인 범위 밖이면 보류) | — |

## 4. 우선순위 개선 제안 (승인 전 구현 금지)

모든 항목은 표시만 바꾸며 피해량·쿨다운·임계값 등 메커닉은 건드리지 않음. 구현은 Development 팀 소유(`LastStopPrototype.cs` HUD 코드). UI 프리팹으로 분리할 경우 위임 필요.

### P0 — 이번 스프린트에 권장

**U1. 50 경고 배너**
- 내용: 내부 적 ≥ 50일 때 상태 패널 바로 아래 전체 폭 배너 `차내 적 50+ · 경고 — 즉시 패배 아님, 피격만 생존력 감소`(문구는 디렉터 확정). 50 미만으로 내려가면 해제. 상태 패널 테두리 빨강.
- 데이터: 기존 `breachWarningActive`(73, 867-875) 그대로 사용.
- 수락 기준: (1) 960x540에서 배너 텍스트 ≥ 18px. (2) 49→50에서 같은 프레임에 표시, 50→49에서 해제. (3) 50 상태에서 HP가 줄지 않음을 Play Mode 프로브로 확인(기존 검증과 동일). (4) 레벨업·결과 화면과 겹치지 않음(레벨업 중 숨김).

**U2. 최소 글자 크기 상향과 텍스트 외곽선**
- 내용: Hit Source 18→22, Mode/Experience 20→22, 레벨업 입력 힌트 18→22(960에서 16.5px). 모든 HUD 텍스트에 1px 검정 `Outline` 또는 `Shadow`.
- 수락 기준: (1) 960x540 캡처에서 모든 HUD 텍스트 ≥ 16px. (2) 각 Text의 `preferredHeight ≤ rect.height`, `preferredWidth ≤ rect.width`를 Play Mode에서 측정해 기록(최장 문자열 기준: `플레이어·코어 피격 ×9 · 생존력 -63`, `50 경고 · 내부 공격 위험`, `꼬치 화염 강화 10`). (3) 피격 플래시 중 빨강 텍스트가 읽힘(캡처 확인).

**U3. 생존력 박스 높이와 HP 바 두께**
- 내용: Shared Health 텍스트 박스를 폰트 ×1.5 이상으로, HP 바를 960 기준 16px 이상으로. 필요하면 상태 패널 높이를 124→132로.
- 수락 기준: (1) `생존력  125 / 125` 등 최대 길이 문자열이 잘리지 않음(preferredHeight 측정). (2) HP 바 높이 ≥ 16px@960x540. (3) R4 악화 방지를 위해 상태 패널 총높이 ≤ 화면 19%.

**U4. 시점 배지와 전환 연출**
- 내용: 상단 중앙 Mode 텍스트를 배지(`외부` 파랑 / `내부` 주황 배경)로 바꾸고, 전환 시 0.12초 화면 플래시 또는 와이프(unscaled time, 입력 막지 않음).
- 수락 기준: (1) 배지 텍스트 ≥ 18px@960. (2) Tab 입력 후 같은 프레임에 배지 변경. (3) 전환 연출 중에도 시뮬레이션·입력이 멈추지 않음(프레임 카운트·적 이동 확인). (4) 연속 Tab 연타에서 연출이 누적되지 않음.

### P1 — 다음 스프린트

**U5. 반대 시점 요약 칩**
- 외부 시점: `내부 적 N · 최근 피격 대상` 칩. 내부 시점: `외부 적 N · 버스 접근 M`(M = 버스 접촉 판정 근처 적 수, 표시 전용 계산).
- 수락 기준: (1) 수치가 `exteriorEnemies.Count`, `interiorEnemies.Count`와 일치(QA 로그 `outside=`/`inside=`와 대조). (2) 계산이 게임 상태를 변경하지 않음.

**U6. 침입 +1 팝업**
- 내용: 침입 시 우측 상단 카운터 옆에 `+1`(같은 0.65초 펄스 창에서 누적 `+N`).
- 수락 기준: 동시 침입 3건 → `+3` 1회 표시, 카운터와 합이 일치.

**U7. HUD가 가리는 전투 영역 축소**
- 내용: 액션 바를 외부 시점에서 반투명/축소, 힌트 토스트를 액션 바 위치와 통합해 하단 점유를 ≤ 15%로. 장비 패널을 내부 시점에서 우측 상단 아래로 이동하거나 6행 시 2열화.
- 수락 기준: (1) 960x540 외부 캡처에서 HUD 점유 세로 비율 ≤ 32%. (2) 장비 6행 상태 내부 캡처에서 출입구 진입 적이 가려지지 않음.

**U8. 위험 단계 문구 정리**
- 내용: 40-49 문구 `위험 · 코어 접근 다수` → `위험 · 내부 적 다수`(실제 계산과 일치). 16/40 구간 유지 여부는 디렉터 결정.
- 수락 기준: 문구가 계산 근거와 일치. 임계값 변경 없음.

**U9. 저체력 비네트**
- 내용: HP ≤ 30%에서 화면 가장자리 붉은 비네트(α ≤ 0.25), 레벨업·결과 중 끔.
- 수락 기준: 30% 경계에서 켜지고 차체 보강으로 30% 초과 시 꺼짐.

### P2 — 여유 시

- U10. 패배 결과에 생존 시간·처치·최고 차내·레벨 추가(도착 화면과 형식 통일). 수락: 두 결과 화면 정보 항목 동일.
- U11. 조작 안내(`A/D 이동`, `Space 공격`, `Tab 전환`) 상시 소형 키캡 영역. 수락: 960에서 ≥ 14px, 전투 영역 미침범.
- U12. 레벨업 카드에 현재 레벨 → 다음 레벨 표기(예: `화염 Lv2 → Lv3`), `일시정지` 라벨. 수락: 카드 텍스트 잘림 없음(U2 측정 방식).
- U13. 장기: HUD를 런타임 코드 생성에서 uGUI 프리팹 또는 UI Toolkit(UXML/USS)으로 분리. Development 팀과 소유권 협의 후 진행. 수락: 기존 HUD 바인딩과 동일한 데이터 표시, `.meta` GUID 보존.

## 5. 인터페이스 / 의존성

- 데이터는 모두 `LastStopPrototype`의 private 필드. 별도 UI 스크립트로 분리하려면 읽기 전용 뷰 모델(예: `SharedHealth`, `SharedMaxHealth`, `InteriorCount`, `ExteriorCount`, `BreachWarningActive`, `ShowingInterior`, `LastHitSummary`)을 노출하는 계약이 필요 — Development 팀 결정.
